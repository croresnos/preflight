# Triage of the 2026-08-06 first pass

Every finding from `2026-08-06-first-pass.md`, and what happened to it. Written
after the fixes, against 0.7.0.

Where a fix is behavioural it names the test that holds it. Where a finding was
closed by a decision rather than a change, the decision is stated.

---

## Blockers

**1. `pip install preflight-gate` does not resolve.** *Open.* The distribution is
built and validated (`python -m build`, `twine check` both pass on 0.7.0) but not
published; publishing needs credentials at a keyboard. Until it is on PyPI the
install line in the README and MANUAL §2 is a promise the index cannot keep.

**2. `try --force` destroyed a hand-written `host.py`.** *Fixed in the code, not
the doc.* `--force` now resets a sandbox `try` itself wrote, and there is no flag
that overwrites a folder preflight did not write. MANUAL §9.6 said this was
already true; it is now. `test_try_will_not_take_over_a_folder_it_did_not_write_even_with_force`
passes `--force` deliberately, because a version that refused without it and
yielded to it would satisfy every other assertion.

## Friction

**3. A saved rule reported as "in force" was ignored.** *Fixed.* The ignore
message named no marker; it now names all four and says to create one. The
generic tail that followed every rejection was written for the other rejection
and read as nonsense on this one — each rejection now carries its own remedy.
`test_a_settings_file_above_an_unmarked_directory_names_the_markers`,
`test_marking_the_directory_makes_the_same_file_apply`. The rejection path had no
test at all before this; it has three now.

**4. §6 stops one step short of loading.** *Fixed, and the shape of the fix
changed.* Rather than documenting a hand-written adapter, a manifest may now name
a module with no `:attribute` — preflight adapts it using the manifest. A package
that never heard of preflight loads after one `create` and nothing else. §6.1
covers both shapes and what the bare one waives. `tests/test_bare_entrypoint.py`.

**5. `check` said "Paperwork is consistent" on a package that could not load.**
*Fixed.* `check` now verifies the `:attribute` half by parsing the module, and
reports it under its own heading — *"a host would refuse this AFTER importing
it"* — because that refusal costs the package its import and every other one does
not. `test_a_package_with_no_create_plugin_is_refused_by_both`,
`test_a_missing_attribute_is_reported_as_costing_the_package_its_import`.

**6. `check`'s suggested next command dropped the path.** *Fixed.* It echoes the
resolved folder, as `create` already did.

**7. `try`'s break instructions were PowerShell-only.** *Fixed, by removing the
per-OS table rather than adding a second one.* The sandbox now ships `break.py`,
and each exercise is `python break.py <n>` — identical in bash, PowerShell, zsh
and cmd, and it prints what it changed. `test_every_break_actually_breaks_the_sandbox_and_its_undo_restores_it`
runs all three and their undos and compares the bytes.

**8. The generated host used `result.get()`, which the manual never documented.**
*Fixed in the manual.* §5 lists `.get`, `.text()` and `.self_reported`, and says
why `.get` is the habit worth forming.

## Polish

**9. README named `load_manifest_file` as importable.** *Fixed:* it is
`PluginRegistry.load_manifest_file`.

**10. No API reference, so the reader used `dir(preflight)`.** *Fixed:* MANUAL
§16, four tables plus an explicit "not part of the API" note.
`test_the_api_reference_names_only_things_that_are_actually_exported` checks it
against `__all__` in both directions.

**11. `create`'s entrypoint guess was smarter than the docs showed.** *Fixed, and
the guess got smarter again:* it now reads the candidate file and only names an
attribute that is there. §6 states the rule.

**12. The README `demo` transcript was missing three lines.** *Fixed, and so was
the hole that let it happen.* `tests/test_transcripts.py` compared in one
direction, so a line the CLI gained never failed. It now also requires every
printed line to be covered by a documented one. Turning that on found **six**
stale blocks, this one among them.

**13. Plain `demo` did not explain the late refusal.** *Fixed:* it ends by
pointing at `preflight demo --refuse destructive`.

**14. `check` with no manifest exits 1 while disclaiming a verdict.** *Fixed in
the doc:* §7.5 says both are true, and that the exit code answers the host's
question because that is what a script is asking.

## What the pass did not cover, and should next time

The tasks were written before the entrypoint had two shapes. A fresh pass should
work `tasks.md` 5 and 5a against each other — the same foreign package adopted
bare, then adopted with `--adapter` — because the choice between them is now the
main thing a newcomer has to understand and nobody has read those docs cold.
